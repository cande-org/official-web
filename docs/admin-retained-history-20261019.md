# 탈퇴 회원 기록을 기존 메뉴에서 조회

탈퇴 계정을 별도 메뉴로 분리하지 않는다. 회원·채팅 기록·결제·광고·친구 목록은 기본 `계정 상태=전체`로 이용 중 계정과 보관된 탈퇴 계정을 함께 표시한다. `이용 중/탈퇴 회원`으로 좁혀 볼 수 있다.

- 이용 중 계정은 UID, 탈퇴 계정은 `보관용 키`로 구분하고 `탈퇴 회원` 배지를 표시한다. 보관용 키는 이전 Auth UID가 아니다.
- 채팅방 앞뒤 대화, 결제/환불·광고 원장과 친구 사진 상세는 기존 화면을 그대로 사용한다. 상세 URL의 `account=deleted`와 보관 키로 조회 출처를 명시해 동명 방/거래를 혼동하지 않는다.
- 회원 상세는 탈퇴일, 탈퇴 당시 잔액, 대화/결제/광고 횟수와 채팅 성공·실패 및 이용권 변동/환급 원장을 제공한다. 보관 키를 푸시 발송 대상으로 사용하지 않는다.
- 회원 상세의 관련 내역 링크는 기존 메뉴에 보관 키·계정 필터를 적용한다. 대화·결제·광고 메뉴의 기존 조회 기간 제한은 유지한다.
- UID·이메일 삭제 정책과 보관 동의 조건을 바꾸지 않는다. 완전히 삭제된 과거 계정/대화는 복구할 수 없다.

서버: mental 저장소 `202610190005_admin_retained_history.sql`, `admin-members`, `admin-chat-history`, `admin-operations`. 기존 Google 관리자 검증, private RPC/RLS, 조회 감사 로그와 사진 10분 서명 URL을 사용한다. 계정 필터를 보내지 않는 구 버전 웹 요청은 이용 중 계정 조회를 유지한다.

검증: `npm run check`, `npm test` 25건, `npm run build`; `chat-history-browser`, `operations-browser`, `members-browser`, `routing-browser` 기존 흐름과 신규 `retained-history-browser` 테스트 통과. 신규 브라우저 검증은 실 사용자 데이터 대신 가상 클라이언트를 사용하며, 혼합 목록·상태/보관 키 필터·동일 ID 상세 구분·이용 원장 페이지·앞뒤 대화·OAuth/새로고침·360/390/430px·지연 응답/로그아웃 정리를 확인한다.
